# 小墨纯表情分支说明（feat/moji-emoji-only）

- 日期：2026-11-08
- 基点：`feat/moji-0.4` 头 `2303625`（含表情扩展设计稿）
- 状态：分支说明，未动代码；脸的几何见 `notes/设计-小墨表情-扩展.md`
- 证据标记：`[码]` 源码 · `[测]` 实测/既有测试 · `[推]` 推断 · `[?]` 待核实

## 0. 这分支是什么

纯表情变体：屏上只有表情，没有中英文文字。**与 0.4 文字版并存，不是替代**——
提醒屏（提醒卡、回复正文、设置页）仍在 0.4 那条线；这条线做纯陪伴。

## 1. 舍弃的

- 机器人头（`robot_face.cpp` 的头框、耳朵、嘴、天线杆 + 球）全部不要。
- 所有中英文文字 UI：回复正文、提醒卡、设置页、状态行、配对码显示。
- 16px 字体问题随之消失（字体表、西班牙语溢出、行盒 22 都不用再管）。

## 2. 留下的

- Otto 眼睛-only 脸：12 态几何见扩展稿（`notes/设计-小墨表情-扩展.md` §3），
  240 帧原样画，不嵌 GIF。底眼统一为高瘦椭圆（见 §3.6）。
- 没有状态点：连接态用脸表示（见 §3）：连接中是转圈脸，连接不上是 XX 眼；
  连上之后就是正常脸（中性即已连接），不需要常驻指示。

## 3. 关键设计点与还没定的

1. **说话态 / 聆听态已重设计（v6，2026-11-08，用户手绘稿）**：眼睛按手绘稿画
   成高瘦椭圆（50×100，(72,112)/(145,112)）。**聆听**：右眼右上方三条弯曲
   线，斜向右上角（wifi 扇形转 ~45°），作耳朵标识；**说话**：眼睛下方一
   个小波形（~50px 宽，居中 (115,205)），不是大嘴。v5 的眼下宽波形、
   v4 的 "(((" 均作废。效果图 `emote-pure-ui-v6.png`。
2. **连接态也用脸（v3，2026-11-08，用户说状态点上下都怪；v7 圈改黄色
   + 转圈特效）**：状态点彻底不要。**连接中**：眼睛 + 黄色转圈环绕整张
   脸（300° 弧、缺口 60°，动画时缺口绕圈转，通用 loading 语言）；**连接
   不上**：XX 眼（机器人脸通用的“坏了 / 离线”）。映射走现有 link 态：
   连接中（黄）→ 转圈脸，连接不上（红）→ XX 眼，已连接（绿）→ 正常脸。
   效果图 `emote-pure-ui-v7.png`，转圈动效 `emote-pure-connecting-spin.gif`。
3. **配网 / 配对码离不开文字**：首次配网选 SSID、输配对码，屏上没字做不了。
   两个口子二选一：① 只在配网时出现一个极简文字页，配完即走；② 配网全走
   手机 App，屏上只显示配网中表情。100% 无文字做不到。
4. **心情驱动是关键路径**：没有 host 心情（Phase 2），纯表情分支大部分时间
   只能显示状态脸（中性 / 聆听 / 思考 / 睡觉 / 困惑），大笑、喜欢、惊讶、眨眼
   用不上。先做 Phase 2 还是先上状态脸，得排个序。
5. **文字提示音**：回复只靠语音播，听不清没法回看——接受，还是留一个
   “点一下重播”的手势？
6. **底眼统一为椭圆形（v8，2026-11-08，用户二选一拍板）**：之前混着不协调
   （聆听/说话是高瘦椭圆，思考/连接是圆形，中性是横杠），现全部状态脸用
   同一只底眼——高瘦椭圆 50×100，(72,112)/(145,112)；状态靠配饰区分
   （聆听右上三条弧、说话眼下小波形、思考眼睛上抬加三个点、惊讶眼上三条
   线、连接黄圈、困惑一大一小加问号）。心情态（开心、难过、大笑、喜欢、
   断开）的眼睛本身就是表情，保持原样；睡觉是闭眼横杠，保持原样。
   圆形眼方案（v8-round）作废。效果图 `emote-pure-ui-v8-oval.png`。
7. **困惑的触发口子还没定**：困惑脸已画好（`Emote::Confused` 已进枚举与
   `emoji_look` 映射），但 app 侧没有触发它的地方——无语音回合目前仍走
   Sad（`app.cpp` 的 VAD NoSpeech 口子）。要拆开的话，得有个能区分的信号
   （比如 host 报识别失败 / 置信度低），等定下来再接。

## 4. 移植顺序

1. 状态脸（neutral / listening / thinking / sleeping / confused）+ 连接态两张脸
   （connecting / disconnected）——**已落地（2026-11-08，第一批）**：
   `firmware/core/src/emoji_face.cpp` + `include/hg/emoji_face.hpp`（新渲染器，
   240 帧，`HG_EMOJI_ZOOM` 默认 1.2），`DeviceProfile` / `BoardConfig` /
   `UiModel` 加 `emoji_face` / `emoji` 开关，moji 板切到 emoji 脸（robot 脸
   留在树里给 0.4 线）。`emoji_look`：link 优先（connecting/network → 转圈，
   offline → XX），再 emote，再 screen。另含 happy / sad（唤醒命中 / 无语音
   回合的 Phase 1 反馈，本来就是状态驱动）与 speaking 静态形（眼下小波形，
   幅度固定）。host 测试 6 项新用例，12px 314 全过、16px 仍是原来 9 败。
   固件实渲染 `emote-pure-firmware-v1.png`，与 v8 原型一致。`Emote::Confused`
   已进枚举与映射，但 app 侧还没有触发它的口子（无语音目前仍走 Sad，
   见 §3.7）。
2. 说话态动画（§3.1 已定稿）：波形幅度随 `level` 起伏。
3. Phase 2 心情 4 态（laughing / loving / surprised / winking）。

## 5. 不做的

- 不引 GIF 解码器、不加 assets 分区、不嵌 941KB GIF（同扩展稿）。
- 不动 `main`、不动 `feat/moji-0.4`；这分支的改动只走这条线。
