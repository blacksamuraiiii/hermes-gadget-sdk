# 小墨表情落地设计稿（moji-0.4 候选）

- 日期：2026-11-05
- 基线：`moji-0.3`（tag `bb67a32`），以下行号均以该基线为准
- 状态：设计稿，未动代码；效果图见 `emote-demo-240.png`（机器人头为风格示意，
  真机画的是 Hermes mascot 女孩像，见 §3）
- 证据标记：`[码]` 源码 · `[测]` 实测/既有测试 · `[推]` 推断 · `[?]` 待核实

## 0. 结论先行

- **只做状态驱动，不做心情驱动**（Phase 1）：6 个 demo 表情里，Listening /
  Thinking / Speaking / Sleeping 全部能从设备已有的状态推出来，**不用改协议、
  不用动 host**；Happy / Sad 各需要一个新位图 + 一个定时覆盖机制，触发点也
  在设备侧找得到（唤醒命中、无语音回合）。
- **不新增任何图片格式**：不引 GIF 解码器，不加 assets 分区。复用 core 现成的
  mascot 管线（1-bit 位图 + `hermes-gadget face` 生成器），新增 2 种帧，
  Flash +约 17.7KB，0.3 的 app 槽余约 1.86MB，放得下。
- **心情驱动是 Phase 2**：回复里的 emoji 现在 host 侧就被 `textfmt` 滤掉了，
  想让大脑的心情传到板子上，要先在 host 侧提取、再走协议，两件事都不在
  Phase 1 做（见 §9）。

## 2. 表情表（Phase 1：7 个名，6 个 demo 位 + Speaking）

| 表情 | 怎么画 | 触发 | 持续 | 回退 |
|---|---|---|---|---|
| `neutral` 中性 | Idle 帧 | 待机（Ready + hero） | 直到变化 | — |
| `listening` 聆听 | Idle 帧 + 耳边声波（已有） | 录音中（Listening） | 到录音结束 | neutral |
| `thinking` 思考 | Idle 帧 + 右上圆点（已有） | 等回答（Thinking） | 到回答开始 | neutral |
| `speaking` 说话 | Talk/Idle 交替（已有） | 播回答且 speaking | 到播完 | neutral |
| `happy` 开心 | **新 Happy 帧** | 唤醒命中（“我在”那一刻） | 3 秒 | neutral |
| `sad` 难过 | **新 Sad 帧** | 回合无语音结束（`cancel_listening("no speech")`，`app.cpp:1156`） | 3 秒 | neutral |
| `sleeping` 睡觉 | **Blink 帧常驻 + 右上角 "Z"**（无新位图） | Ready + hero 且闲置 ≥120 秒 | 到任何动静 | neutral |

不做的（demo 里有、Phase 1 不做）：`pet`（无触摸头顶，改走 BOOT 点按是二期议题）、
`shake`（无 IMU）、`look_left/right`（无舵机）、`email`（提醒卡片已在 0.3 落地，
不需要单独一张脸）。别名表（loving→happy、crying→sad、sleepy→sleeping 等）
Phase 1 只在代码里留一张最小映射，供 Phase 2 的 `face` 动作复用，不单独做入口。

## 3. 先说清楚：demo 画的机器人头不是真机会画的

`emote-demo-240.png` 里是机器人头，那是风格示意。真机画的是 Hermes mascot
（`assets/mascot/nous-girl-white-1024.png`，白线条女孩像），Happy/Sad 必须在
这张像上派生，不能把 demo 的机器人头直接当美术稿。验收时以生成器的
`face-check.png`（眼睛/嘴/锚点落位图）为准，不以 demo 图为准。

## 4. 帧方案：只新增 Happy、Sad 两种位图

每种帧 × 四档尺寸的 Flash 账（1-bit，`尺寸²/8`）`[码]`：

| 尺寸 | 字节 |
|---|---|
| 64 | 512 |
| 96 | 1152 |
| 144 | 2592 |
| 192 | 4608 |
| **合计/帧** | **8864（约 8.7KB）** |

新增 Happy + Sad = **约 17.7KB**。`mascot_data.cpp` 源码会变大六倍左右
（十六进制文本），那是源码体积，不是 Flash 体积，别被吓到。

### Happy 帧：从 master alpha 派生（仿 `mascot_frames()` 的 Blink 做法）

1. 盖住两只眼睛的多边形（`MASCOT["right_eye"]` / `["left_eye"]`，`face.py:44-49`），
   改画上弯的眼睑弧线（∩ 形，笑眼），线宽沿用 `lid` 的 12–14（master px）。
2. 嘴部：把 `mouth_open` 椭圆（246, 622, 292, 648）放大约 1.6 倍再挖洞，
   得张开的笑口。放大系数以 `face-preview.png` 上 192px 看着像笑为准，
   不钉死数字，调一次、看一次。
3. 其余像素与 Idle 完全相同。

### Sad 帧：从 master alpha 派生

1. 眼睛不动（睁着）。在左眼下方加一滴泪：以左眼中心（235, 481）为准
   （`test_face.py` 钉住的实测几何），向下约 40 master px 处画一个泪滴
   （小圆 + 尖顶，约 14×20 master px），泪滴是墨（白），不是挖洞。
2. 嘴部：盖住原嘴区，改画下弯的弧线（∩ 形，撇嘴），线宽与眼睑线一致。
3. 其余像素与 Idle 完全相同。

### Sleeping：不新增位图

- 帧用 Blink（闭眼的眼睑线就是睡觉的眼睛），由选帧逻辑常驻 Blink。
- "Z" 由固件在 `draw_hero()` 里用 `Canvas::text()` 画在右上角锚点
  （`head_top_right`，与思考圆点同一位置），"Z" 是 ASCII，现有字体就能画。
- 泪滴/“Z” 的脏区见 §5。

### 可见度底线（照 `test_face.py` 的规矩）

Blink 在 192px 改 226 bits、Talk 改 16 bits `[测]`。新帧验收时同样量：
Happy、Sad 在 192px 与 Idle 的差异 bits 数写进测试，底线先定 **≥100 bits**
（Blink 的一半不到；低于它就是“换了等于没换”，按静默失败处理）。
具体数字以第一版生成结果为准，测试里钉死实测值，不拍脑袋。

## 5. 选帧与绘制：改四处，都在 core 里

### 5.1 `firmware/core/include/hg/mascot.hpp`：帧枚举加两种

```cpp
enum class Frame : uint8_t { Idle, Blink, Talk, Happy, Sad };
```

`pick()` 不用动（它按帧名查表）。`Anchors` 不用加字段——泪滴和 "Z"
的位置由 `hero_anim_rows()` 用现有锚点推导（§5.4）。

### 5.2 `firmware/core/include/hg/ui.hpp`：`UiModel` 加一个字段

```cpp
enum class Emote : uint8_t { Auto, Happy, Sad, Sleeping };
struct UiModel {
  // ...
  Emote emote = Emote::Auto;  // 定时覆盖或睡觉；Auto = 按 screen 推导
};
```

`Emote` 放 `ui.hpp` 而不用 `mascot::Frame`，因为 Sleeping 不是位图
（它是 Blink + "Z"），选帧函数需要区分“哪张位图”和“画不画 Z”。

### 5.3 `firmware/core/src/app.cpp`：`update_model()` 里定 emote

App 新增两个成员（`app.hpp`）：

```cpp
uint32_t idle_since_ = 0;     // 上次非 Idle 的时刻（tick 里维护）
uint32_t emote_until_ = 0;    // 定时覆盖的到期时刻
Emote emote_override_ = Emote::Auto;
```

- `tick()` 里：`mode_ != Mode::Idle` 时 `idle_since_ = t`（一处维护，
  不用满世界找 mode 赋值点）。`[推]`：mode 的每次切换都经过 tick，
  漏不掉。
- `update_model()` 末尾（`render(m)` 之前）定 `m.emote`：
  1. 定时覆盖未到期 → `emote_override_`（Happy/Sad，3 秒）。
  2. 否则 `screen == Ready && hero && t - idle_since_ >= 120000
     && !display_sleeping_` → `Sleeping`。
  3. 否则 `Auto`。
- 触发点（只加两行调用，不改原有流程）：
  - 唤醒命中：`on_wake_hit()` 里 `set_emote(Happy, 3000)`。
  - 无语音回合结束：`cancel_listening("no speech")` 处（`app.cpp:1156`）
    `set_emote(Sad, 3000)`。
  - `set_emote()` 是 App 的私有小函数：写 `emote_override_` +
    `emote_until_ = now() + ms` + `update_model()`。

### 5.4 `firmware/core/src/ui.cpp`：选帧、脏区、画 "Z"

`mascot_frame()` 改成：

```cpp
mascot::Frame mascot_frame(const UiModel& m) {
  if (m.emote == Emote::Happy) return mascot::Frame::Happy;
  if (m.emote == Emote::Sad) return mascot::Frame::Sad;
  if (m.emote == Emote::Sleeping) return mascot::Frame::Blink;  // 闭眼常驻
  if (m.screen == Screen::Responding && m.speaking)
    return (m.frame / 2) % 2 ? mascot::Frame::Talk : mascot::Frame::Idle;
  return m.frame % 45 < 2 ? mascot::Frame::Blink : mascot::Frame::Idle;
}
```

注意：**说话优先于心情**。播回答时即使 Happy 覆盖未到期也画 Talk，
播完再恢复心情。这是有意取舍（nous-girl 是按心情配嘴型，我们没有
Happy+Talk 的组合帧），写进已知边界，不偷偷改。

`hero_anim_key()`：`mascot_frame(m)` 已在 key 里（`ui.cpp:109`），
emote 变化自动触发重画，不用另加；但 Sleeping 的 "Z" 是文本覆盖物，
Blink 帧常驻时 `m.frame % 45` 的 Blink 节律还在——`mascot_frame()`
返回 Blink 时 key 不随 frame 变，**"Z" 不会闪**，符合预期。
反过来要确认：Sleeping 期间 `hero_anim_key()` 必须稳定，否则 100ms
一帧全量重画。验收时看 `frame_stats`（见 §7）。

`hero_anim_rows()`：Sleeping 复用 Thinking 分支的脏区
（`head_top_right` 上下 `size/6`，`ui.cpp:769-772`），"Z" 就画在那；
Sad 的泪滴在左眼下方，底边要比 `eyes_y1` 再往下扩 `size * 120 / 1000`，
否则泪滴残影擦不掉。脏区扩多少以真机为准，先写 120/1000 这个数，
验收项里有“泪滴不留残影”。

`draw_hero()`：`m.emote == Emote::Sleeping` 时，在 `head_top_right`
锚点画 "Z"（`Canvas::text()`，scale `s`，颜色 `kText`）。
只画一个 "Z" 还是 "Z z" 两个，看 192px 实际大小定，不钉死。

## 6. 生成器改动（`python/hermes_gadget/face.py` + 测试）

1. `FRAMES` 从 `("idle", "blink", "talk")` 扩到
   `("idle", "blink", "talk", "happy", "sad")`；`mascot_frames()` 加
   §4 的两种派生；`emit()` 的表随之多 8 个数组（2 帧 × 4 档）。
2. 派生参数（眼睑弧线曲率、嘴放大系数、泪滴位置）先写常量，
   以 `face-check.png` / `face-preview.png` 调一轮为准，不追求一次到位。
3. `tests/test_face.py` 同步改四处：
   - 数组数 12 → 20，`EXPECTED` 里加 Happy/Sad；
   - blink/talk 的 226/16 bits 断言不动，加 Happy/Sad 的实测 bits 断言
     （值以生成结果为准，底线 §4）；
   - “生成器重跑与已提交文件逐字节一致”的测试：Happy/Sad 进文件后，
     该测试仍须通过（即提交时必须用新版生成器重跑过全文件，不是手改）；
   - 通用 profile（`generic_frames`）不动——本设计只动 mascot profile，
     别人画的像不受影响。
4. `docs/faces.md` 补一段：三帧变五帧，Happy/Sad 怎么派生的，
   `hermes-gadget face` 的预览图怎么看。

## 9. Phase 2（心情驱动，不在本文范围，只留口子）

- Host 侧：`adapter.py` 的 `send()` / `_synthesize_auto_tts()` 在
  `textfmt` 滤 emoji **之前**，取回复首个 emoji，按 nous-girl 的
  emoji→心情表（😂 funny、😭 crying、😠 angry、😔 sad、😍 loving……
  出自上游 `textUtils.py`）映射到 emote 名。
- 协议：不用新消息类型。`App::h_action()` 已有通用动作分发
  （`app.cpp:827`，按名查 `actions_` 注册表并回 `action.result`），
  Phase 2 注册一个 `face` 动作：
  `{"type": "action", "name": "face", "args": {"emote": "happy", "ttl_s": 3}}`，
  固件校验名字在表里才接受（未知名回错，不画）。
- 插件侧：`hermes gadget face <device> <emote>`（仿 0.3 的 `show`
  的 CardStore 模式，或直调 hub action），供测试与脚本调用；
  另在 gadget profile 的 SOUL.md 加一行使用时机。
- 别名表（loving→happy 等）Phase 2 随 `face` 动作一起落地，
  Phase 1 只留最小映射占位。
- 不做的提醒：心情只在 hero 可见时画；Card/Prompt/Dashboard 屏不画脸，
  别指望 `face` 动作在任何屏都生效。

## 10. 风险与未决

1. **美术风险**：Happy/Sad 的派生参数（弧线、嘴放大、泪滴）没有现成
   数字，第一版很可能“笑得不像笑、哭得不像哭”，要留一轮调参时间，
   以 `face-preview.png` 为准，不以 demo 图为准。
2. **Sleeping 与屏幕超时的关系**：`screen_timeout` 默认 0（永不），
   moji 是 USB 供电，120 秒睡觉脸看得到；如果用户改短了超时，
   屏先睡了，睡觉脸永远看不到——这是设置问题，不是 bug，验收时确认
   当前设置值。
3. **说话压住心情**（§5.4）是取舍，不是遗漏；想做心情嘴型要再加
   Happy+Talk / Sad+Talk 组合帧，Phase 2 再议。
4. **唤醒命中 → Happy 的触发在 `on_wake_hit()`**：0.3 里命中是先播
   “我在”再开录音，Happy 的 3 秒会和录音重叠——录音中是 Listening
   屏，Happy 画不出来。实际效果是：命中瞬间闪一下 Happy，随即切
   Listening。能接受（就是“听到你了”的意思），但别指望 Happy 能
   看满 3 秒；真想看满，触发点改到回合结束，Phase 1 不改。
5. **Blink 节律**：`m.frame % 45 < 2` 的眨眼在 Sleeping 时被常驻
   Blink 取代，醒来后节律从断点续上，不用复位。
6. 本设计稿未动代码；美术稿（派生参数）与 `face` 动作的协议细节
   （字段名、ttl 上限、未知名的错误文案）留待实现时最后定。
