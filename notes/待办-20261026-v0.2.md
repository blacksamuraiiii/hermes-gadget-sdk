### 1H 回合卡死：发不出去的信也进 Thinking，屏幕停在 responding（已完成 2026-10-26）

**已修（`app.cpp`，host 288 例 0 失败，已烧录实测）**

- 发送失败不再进 Thinking：`submit_text()` 里 `send()` 返回 false 时给 `NotConnected` 提示并 return。此前 `can_talk()` 通过后链路瞬断，消息丢了却照样进 Thinking。
- Responding 加超时兜底：`t - last_turn_rx_ > kThinkingTimeoutMs`（180 s）且不在放音时，回 Idle 并提示 `NoReplyFromHermes`。此前只有 Thinking 有超时，回合中途断链就永久停在 Responding，卡片和提醒都覆盖不上。
- 两条新用例：`a text that cannot be sent does not enter Thinking`、`a turn that goes quiet leaves Responding by itself`。
- 实机核对：断链状态下 `say` 后 `status` 为 `screen: boot/connecting`，不再出现 `responding`；链路恢复后 `gadget_display` 卡片正常上屏。

原症状（留档）：

现象：`submit_text()` 判过 `can_talk()` 后立刻置 `Mode::Thinking`、清空 `reply_`，但 `send()` 可能因链路瞬断而丢帧；此后没有回合超时回退，`status` 长期显示 `screen: "responding"`，卡片等提醒也覆盖不上，只能靠 console `cancel` 解开。
证据：本次字体验证时三次 `say` 之后设备卡在 responding，`cancel` 后恢复。
建议：回合起后设上限（如 30 s 无 `turn.*` 到达则回 idle 并提示），与 1E 空回合同源，可一并处理。
验收：链路断开时 `say` 一句，屏幕在 N 秒内自行回到可显示卡片的状态。

### 1G GB2312 二级字库：决策点（P2，可进 0.2 也可推迟）

**已完成 2026-10-26（生成 + 构建 + 烧录；屏幕验证待拔插 USB 后补）**

- 源：Fusion Pixel 12px monospaced zh_hans v2026.10.25 的 BDF（GitHub release，35.7 MB，走 172.18.176.1:7890 代理下载）。
- 生成：`python tools/make_cjk_font.py --bdf ... --charset gb2312`。表内实收 **6647 字**（一级 3755 全覆盖，二级 2892/3008），BDF 本身缺 116 个二级字（鼗劐衮谮郄垡墼墚苁芪茚…），这些仍显示 `?`。
- 体积：app 0x155ec0 → 0x169b10（+79 KB），槽余 31% → 27%。
- 验证：host 288 例 0 失败；esptool 烧录 `Hash of data verified`。
- 生成器补齐：重新生成会覆盖手写的 `bitmap()`/`ascii_rows()` 适配层，已把它写进 `make_cjk_font.py`，避免下次重生成后链接失败。
- 一致性核对：ASCII 1140 字节与手工转换结果逐字节相同（说明 6 位左移 2 的对齐处理正确）。

原决策点：

现状证据：v0.1 字库为 GB2312 一级 3755 字约 105 KB；app 1,405,952 B，槽 `0x1F0000` 余约 625 KB（31%）；README 称升二级需 +60% 空间。

- [ ] 实测二级字库的真实增量（重新生成一次，不要凭 +60% 估算），并确认 app 槽余量与 OTA 槽不受影响。
- [ ] 决策（用户拍板）：进 0.2（提醒卡片常含人名/地名，罕字 `?` 影响大）或推迟到 0.3（先保唤醒进度）。
- 验收（若进 0.2）：二级常用字实测上屏；`text_cols/rows` 不变；app 大小与槽余量更新到 releases README。

## 任务 3 · MultiNet 命名词设计

> 设计稿已落盘：`设计-语音唤醒.md`（选型、模型与命令词、分区、采样率、代码接缝、资源账、测试门槛、风险、里程碑）。本节保留任务清单与原始依据。

### 3.0 选型结论（不再反复论证，直接作为 0.2 前提）

- **不用 WakeNet（AFE 版）**：唤醒词是乐鑫训练好的固定词表，任意自定义词要走乐鑫定制服务；AFE 的 AEC 需要播放参考通道，moji 是 ES8311 单模拟麦，没有干净参考，硬上效果没保证。
- **用 MultiNet 命令词**：就是小智的 `USE_CUSTOM_WAKE_WORD` 那条路——拼音定义任意短语、阈值可调，组件用官方 `espressif/esp-sr`（小智钉 `2.4.7` 作参考，实际版本以 Hermes 的 IDF 6.1 与 Component Registry 兼容性核实为准），不自己训模型、不自己写检测器。
- **不做“说话就唤醒”（纯能量 VAD 触发）**：那是 0.1 刚切掉的空回合 bug 的复活版——任何说话/噪声都起回合，代价不可控。能量 VAD 只作唤醒后的“确认有人在说话”辅助，不作唤醒判据本身。

### 3.1 命名原则（选词前先过这 6 条）

1. **3–4 音节**：2 音节误触高，5 音节以上喊着累、漏检高；小智默认自定义词 `xiao tu dou` 就是 3 音节。
2. **日常对话里极少连说**：不能是问候语、常用词、Hermes 命令里已有的短语；连说的概率直接决定误唤醒率。
3. **音节区分度高**：避免同音/近音高频词（如 `小明 / 小米 / 小墨水` 这种近音簇）；声母、韵母、声调尽量拉开。
4. **与设备身份绑定**：优先贴合“墨迹板 / Hermes”身份，用户不用记一套与设备无关的暗号。
5. **拼音可直写**：MultiNet 命令就是拼音串（空格分隔），选词时就要同时定拼音，避免多音字、方言音歧义。
6. **主词 + 备选成对定**：主词一旦在实测中误触/漏检超标，不用重新立项，直接切备选。

### 3.2 候选词表（待用户拍板 1 主 + 1 备）

| 候选 | 拼音（MultiNet 命令串） | 音节 | 优点 | 风险 / 注意 |
|---|---|---|---|---|
| **A（推荐主词）你好小墨** | `ni hao xiao mo` | 4 | 贴合墨迹板身份；“你好 + 设备名”符合中文唤醒习惯；日常对话里连说概率低 | “你好”本身是高频问候，需靠后两音节 `xiao mo` 兜底；测试时重点测“你好 + 其他词”的误触 |
| **B（推荐备选）小墨小墨** | `xiao mo xiao mo` | 4 | 叠词结构区分度最高，MultiNet 最容易检出；喊两遍本身就是“确认意图” | 日常叫设备名时若只喊一遍不会触发（符合预期），但用户要养成喊两遍的习惯 |
| C 嘿小墨 | `hei xiao mo` | 3 | 最短、最顺口 | `hei` 是高频口头禅/招呼音，误触风险三者最高；只建议阈值收紧后作对照组，不建议作主词 |
| D 你好莫吉 | `ni hao mo ji` | 4 | 音译 moji，与板名直连 | `mo ji` 与“墨迹”同音，日常说“墨迹”（拖沓）时可能误触；且 `ji` 在方言/儿化音里易漂移 |

- 决策点（用户拍板）：主词选 A 还是 B；C、D 是否保留作对照组（建议只留一个对照组，测试量翻倍没有意义）。
- 不做：英文词（如 `hey hermes`）——MultiNet 中文模型对英文音节的检出不稳定，且与中文使用场景不贴合；`你好赫尔墨斯`（6 音节，太长）不考虑。

### 3.3 阈值与测试设计（数字先行，不凭感觉调）

- 阈值基线：照小智默认 `CUSTOM_WAKE_WORD_THRESHOLD = 20`（范围 1–99，**数值越小越灵敏**，`threshold_ = 值 / 100`），扫描点定为 **15 / 20 / 25** 三档，不逐 1 微调。
- 正样本：3 位说话人（至少含用户本人）× 距离 0.5 / 1 / 2 / 3 米 × 安静 / 日常噪声（电视、谈话声）两档，每档 ≥ 20 遍。
- 负样本（误触库，必须录）：日常对话 30 分钟、电视/视频 30 分钟、近音短语各 20 遍——`你好小明、你好小莫、小墨水、你好吗、墨迹、嘿、小墨`（单喊一遍）。
- 指标与 0.2 门槛（建议值，用户可改，改了就按改的算）：
  - 1 米安静漏唤醒率 ≤ 5%；3 米安静漏唤醒率 ≤ 20%。
  - 负样本误唤醒：日常对话 + 电视合计 ≤ 1 次/小时。
  - 播放自唤醒：cue / TTS 播放期间误唤醒 = 0 次（见 3.4 播放静默）。
  - 命中到亮屏延迟：从词尾到屏幕亮起 ≤ 1 s（USB 直连链路，不含模型推理排队）。
- 记录格式：每次测试记“词 / 阈值 / 说话人 / 距离 / 噪声档 / 命中与否 / 延迟”，阈值扫描表附在 notes 里，不只记结论。

### 3.4 落地检查清单（命名定下来之后，引擎按这个顺序接）

- [ ] **模型分区（板级，不动全局分区表）**：moji 单独一份带 `model` 分区的分区表（小智 v1 给模型留 960 KB 作参考，实际以 esp-sr 选中模型的体积核实）；整片重刷说明写进 releases README，OTA 布局变更明示。
- [ ] **组件钉版本**：`idf_component.yml` 里 esp-sr 走 Kconfig 门控、仅 moji 板启用（其余板不受影响）；版本以 IDF 6.1 兼容性实测为准，不照抄小智的 `2.4.7` 当结论。
- [ ] **采样率**：codec 照跑 24 kHz，用官方 `esp_audio_effects` 的 rate_cvt 做 24 kHz → 16 kHz 重采样给 MultiNet（小智同款做法），不手写重采样。
- [ ] **常开麦路径**：唤醒引擎放在 port 层常开跑——Hermes core 现在麦克风按键才开、非 Listening 样本直接丢，命中后以“等效一次 Talk 按键事件”进 core 状态机；`audio.start` 用上游预留的 `mode` 字段标 `wake`，不改 App 状态机大结构（`vad.hpp` 注释本身就留了这个接缝）。
- [ ] **播放静默**：cue / TTS 播放期间停检测（单麦无 AEC，设备自己的声音会把自己唤醒）；播放结束恢复检测，恢复时清掉播放期间缓存的音频。
- [ ] **空转写守门共用**：任务 1E 的守门必须先于唤醒上线——误唤醒进来也先过空转写闸，唤醒才敢放开阈值。
- [ ] **资源账**：实测并记录 MultiNet 模型 Flash 占用、PSRAM 占用、常开检测时的 CPU 占用与 USB 链路带宽（24 kHz PCM16 常开流经 relay 的量），三项都进 0.2 发布说明。
- [ ] **回退**：唤醒关掉后 BOOT 按键说话必须原样可用；Kconfig 默认关（`HG_WAKE_MULTINET` 默认 n），只在 moji 板上开。
- [ ] **后续命令词预留（0.2 不做，只留口子）**：MultiNet 可注册多条命令，0.2 只注册唤醒词一条；“停下 / 取消”这类命令词留到 0.3 评估，不在本版扩命令表。
