# 设计：语音唤醒（MultiNet 命令词，moji 板）

- 状态：设计稿（2026-10-26）。未写代码、未上机。
- 拍板前提（`决策-台账.md` 2026-10-26）：主词 `你好小墨`（`ni hao xiao mo`），备词 `小墨小墨`（`xiao mo xiao mo`）；**命中后只亮屏 + 提示文案，语音回合仍关闭**，命令词口子留到 0.3。
- 0.2 交付：板级可开关的唤醒检测 + 亮屏提示 + 阈值扫描记录表；不做「唤醒即对话」。

## 1 选型结论（不再论证）

| 方案 | 结论 | 理由 |
|---|---|---|
| WakeNet（AFE 版） | 不用 | 唤醒词是乐鑫固定词表，自定义要走定制服务；AEC 需要播放参考通道，本板 ES8311 单模拟麦没有干净参考 |
| **MultiNet 命令词** | **采用** | 拼音定义任意短语、阈值可调，官方组件；单麦可用（不启用 AEC） |
| 能量 VAD 当唤醒 | 不用 | 等于 0.1 的空回合 bug 复活；VAD 只做「唤醒后确认有人说话」 |

## 2 模型与命令词

- 官方中文模型（esp-sr `Kconfig.projbuild`，`depends on IDF_TARGET_ESP32S3`）：
  `SR_MN_CN_MULTINET5_RECOGNITION_QUANT8`（mn5q8_cn）、`SR_MN_CN_MULTINET6_QUANT`（mn6_cn）、`SR_MN_CN_MULTINET7_QUANT`（mn7_cn）。
- **第一步用 `mn5q8_cn`**：它的命令词是 Kconfig 字符串（`CN_SPEECH_COMMAND_ID0..`，默认值就是 `da kai kong tiao` 这种拼音），改命令词不用动组件文件，和小智同路，风险最低。
- 第二步再评估 `mn6_cn`（官方英文基准 MultiNet6 的 WER 比 5 低一半）：它不使用 Kconfig 命令串，命令词要经运行时 API 或组件内 `commands_cn` 文件，改动面更大。命令词始终只注册两条（主/备），备词用于主词误触超标时切换。
- 阈值起点照小智 `CUSTOM_WAKE_WORD_THRESHOLD = 20`（1–99，**越小越灵敏**），扫描点 15 / 20 / 25。

## 3 分区与烧写（最容易踩的一条）

- esp-sr 要求分区表里有标签为 `model` 的分区：官方写法 `model, data, , , 6000K`（按所选模型定大小）。
- 本板 16 MB Flash，`firmware/esp32/partitions.csv` 目前只用到 `0x400000`，**后面 12 MB 未分配**。设计：在 `0x400000` 起划 `model` 分区，先用 **4 MB**（`0x400000`–`0x800000`），两个 `ota_*` 槽与 otadata 的 offset/大小都不动。
- **模型不在 app 镜像里**：`idf.py flash` 会连带写 model 分区，`idf.py app-flash` 不会。发版包必须单独带 `srmodels.bin` 与写入地址，README 写清；OTA 只替换 app 槽，不碰 model 分区（esp-sr 设计如此）。
- 首次上机属**分区布局变更**，必须整片重刷（`write-flash` 全四件 + srmodels），不能只 OTA。

## 4 采样率与前端

- codec 是 24 kHz（板级 `AUDIO_INPUT_SAMPLE_RATE`），MultiNet 的输入是 AFE 输出的 16 kHz PCM16 单声道。
- 重采样用官方组件（xiaozhi 同款 `esp_audio_effects` / `rate_cvt`），不手写。
- AFE 用 `MR, SR, LOW_COST` 档（单麦、无 AEC）：官方基准 60.1 KB 内部 RAM + 739.7 KB PSRAM、约 9% 单核 CPU。**不启用 AEC**——没有干净参考通道，硬上不如「播放静默」。
- 播放静默：cue / TTS 播放期间停检测（`AudioOut::busy()` 为真即静音期），播放结束恢复，并丢弃播放期间缓存的帧。

## 5 代码接缝（本仓现状）

- 麦克风是**独占**的：`AudioIn::start(rate)` 之后由 port 持续回调 `App::on_mic_samples()`，`stop()` 结束（`firmware/core/include/hg/hal.hpp:51-58`）。talk 路径在 `App::start_listening()` 里 `hal_.mic->start(profile_.mic_rate)`（`firmware/core/src/app.cpp:968`），`finish_listening()` 里 `stop()`（`:998`）。
- 因此唤醒引擎不能自己再开一路 mic。设计：
  1. 新增 `firmware/esp32/main/port_wake.cpp`（编译期由 `CONFIG_HG_WAKE_MULTINET` 门控），提供 `wake_begin() / wake_pause() / wake_resume()` 与内部任务；它通过同一 `AudioIn` 取 40 ms 帧。
  2. core 只加两处最小接线：`start_listening()` 前 `wake_pause()`；`finish_listening()` 后 `wake_resume()`。空实现由 HAL 的弱符号给，其他板零改动。
  3. 命中回调 `App::on_wake_detected()`：点亮屏幕 + 显示提示（复用现有 hint/overlay 与屏幕唤醒路径），**不改 `Mode`、不发 `audio.start`**——这是「只亮屏」的落点。
- 不引入 `audio.start` 的 `mode=wake`（上游预留字段）。理由：本轮不起回合，用不上；0.3 要起回合时再按上游字段补齐，避免现在改协议。

## 6 Kconfig 与板级开关

- `main/Kconfig.projbuild`：`HG_WAKE_MULTINET`（bool，默认 **n**）、`HG_WAKE_THRESHOLD`（int，默认 20）、`HG_WAKE_WORD`（string，默认 `ni hao xiao mo`），全部 `depends on HG_BOARD_MOVECALL_MOJI`，并在 `boards/movecall-moji-esp32s3/sdkconfig.defaults` 里显式开。
- `main/idf_component.yml`：`espressif/esp-sr` 走 Kconfig 门控，加 `rules: - if: "$HG_WAKE_MULTINET"`（语法以组件管理要求为准），其余板不拉这个 175 MB 的组件。
- 默认关，回退即「BOOT 按键说话」原样可用。

## 7 资源账（官方基准 + 本板必测）

| 项 | 官方基准（ESP32-S3） | 本板待实测 |
|---|---|---|
| MultiNet5 Q8 | 16 KB 内部 RAM + 2310 KB PSRAM，12 ms/32 ms 帧 | PSRAM 实占、CPU |
| MultiNet6 | 32 KB + 4100 KB PSRAM，12 ms/32 ms 帧 | 同上（若换 6） |
| AFE（MR, SR, LOW_COST） | 60.1 KB + 739.7 KB PSRAM，约 9% 单核 | 与 USB 链路共存时的 CPU |
| 模型 Flash | 以生成的 `srmodels.bin` 为准 | 分区实占（先按 4 MB 规划） |
| USB 带宽 | 常开麦不经过 USB：唤醒在设备侧完成，命中只发一条事件 | 事件报文大小 |
| 帧缓冲 | — | 112.5 KB PSRAM（已有），与模型共存后的剩余 |

三项（Flash / PSRAM / CPU）必须实测后写进 0.2 发布说明，不用估算值。

## 8 测试与门槛（沿用 3.3，补两条）

- 先离线再上机：录 24 kHz wav → PC 侧重采样 16 kHz → 喂 MultiNet（官方 example 的离线模式）先确认「命令词可被检出」，再上板扫阈值。省掉在板上一遍遍喊。
- 真机矩阵：3 位说话人 × 0.5/1/2/3 m × 安静/日常噪声两档，每档 ≥20 遍；负样本库：日常对话 30 min、电视 30 min、近音短语各 20 遍（`你好小明`、`你好小莫`、`小墨水`、`你好吗`、`墨迹`、`嘿`、单喊一遍 `小墨`）。
- 门槛（用户可改）：1 m 安静漏唤醒 ≤5%，3 m ≤20%；负样本合计误唤醒 ≤1 次/小时；播放期自唤醒 0 次；词尾到亮屏 ≤1 s。
- 记录表：词 / 阈值 / 说话人 / 距离 / 噪声档 / 命中 / 延迟，附在 `验收-唤醒阈值扫描.md`（0.2 新建）。

## 9 风险

| # | 风险 | 判据 / 缓解 |
|---|---|---|
| R1 | esp-sr 2.6.0 与本机 IDF（git 快照 `9a97f6c5`）不兼容 | 用独立 build 目录先装一次；失败就退到与小智同版本的 esp-sr |
| R2 | 组件包 175 MB，国内下载慢/断 | 用 Component Registry 镜像或预先下载；失败不阻塞主线 |
| R3 | 24k→16k 重采样引入延迟/失真，检出率下降 | 离线回放对比：直采 16k 录音 vs 24k 重采样，逐条比命中 |
| R4 | 常开麦与 talk 抢 mic 导致录音丢帧 | 互斥只在 `start_listening`/`finish_listening` 两个点；上机看 `audio.start` 后首帧时间 |
| R5 | 模型分区规划过大/过小 | 生成一次 `srmodels.bin` 后按实际大小定 4 MB 是否够 |
| R6 | 唤醒误触把屏幕频繁点亮，反而扰人 | 误唤醒指标 + 亮屏节流（同一次命中后 N 秒内不再亮） |

## 10 里程碑

1. 组件与模型落地：独立 build 目录装 esp-sr → 生成 `srmodels.bin` → 量实际大小 → 定分区（不动机上固件）。
2. 离线验证：PC 侧重采样 + 官方 example 跑通两条命令词。
3. 板上接线：`port_wake.cpp` + core 两处互斥 + 亮屏提示，`HG_WAKE_MULTINET=n` 提交（默认关，可回退）。
4. 阈值扫描与记录表；定主词或切备词。
5. 发布：分区变更写进 releases README，`srmodels.bin` 单独给地址与校验值。
