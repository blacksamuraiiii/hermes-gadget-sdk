# 设计：16 px 字体与圆屏版面（moji 0.4）

适用：`movecall-moji-esp32s3`（240×240 GC9A01 圆屏、无触摸、单 BOOT 键）。
本文记录 2026-11-06 这一轮把「英文看不清、正文被吃行、黄点被弧线切」一起收口的选型与实测。

## 1. 结论先行

| 项 | 定案 |
|---|---|
| 字体 | **思源/Noto Sans SC Medium 一套通吃中英**（弃 Montserrat 双字） |
| 中文 | 16 px ink，画在 **22 px 行盒**（rows 3..18） |
| 英文 | **em16**（同一个 Noto），大写墨高 11 px，基线 16，下探部到 row 19/20 |
| 为什么是一套字 | 生态（xiaozhi-fonts）即此做法；实测 Noto 拉丁 em16 平均 advance 9.4 px ≈ 8 px/列，**列宽系统零改动** |
| 行数 | `body_rows_cap = 4`（顶带让位后文本带仍 5 行容量） |
| 顶带 | 无触摸板 → 只作弧线让位带，固定 **36 px**（与旧标签带同高） |
| 状态点 | 文本页：Running 呼吸（13→20 px 循环），Ready 实心 r×2/3 不动；脸页：**天线球当连接灯**（绿在线/黄连接中/红离线），顶部独立小点取消 |
| 温度 | 字表含 `℃`/`°`，`fold_to_font` 把 `°C`/`°F` 折成 `℃`，遥控文本进显示前统一 fold |

## 2. 为什么放弃 Montserrat 双字（把弯路记下来）

- 原生成器 `latin_px = cell * 0.75`：16 px 表里英文只有 **em12**，大写墨高 8.4 px，比汉字矮一截；
  且 1× 二值化阈值 110 会把细横笔吃掉——实测 `T` 只剩竖条（"Thinking" 看着像 "Ihinking"）、
  `j` 丢底钩、`E/F` 上横只剩两点。真机照片与模拟器都能复现。
- 试过把英文抬到 **Montserrat em22**（cap 15 px ≈ 汉字）：墨高够了，但 Montserrat em22 平均
  advance 13.5 px，**1 字符远超 1 列（8 px）**，整个「列数排版」系统被撑爆——换行、fit、
  西语词表、约 20 条测试全要跟着改。这是本次绕远的主因，已整体回退。
- 思源拉丁 em16 的 advance 分布（实测）：`i/l=5`、`e=11`、`n=12`、`m=15`、`M=14`、`W=14`，
  平均 9.4 px → 逐字最近列取整后几乎回到「1 字符=1 列」，既有系统无需改动。

## 3. 字体生成（tools/make_cjk_font.py）

```bash
python tools/make_cjk_font.py \
  --latin  NotoSansSC-Medium.otf --cjk NotoSansSC-Medium.otf \
  --px 16 --pitch 22 --latin-em 16 --latin-base 16 --cjk-y=-2
```

- **行盒模式**（`--pitch`）：两张表都按 22 行输出；CJK 用 `--cjk-y` 把 em 盒下推，墨迹落在 rows 3..18；
  拉丁用 `--latin-base` 把基线钉在 row 16，大写 4..15、下探部 16..20，与汉字同基线。
- **拉丁 4× 超采样 + 阈值 100**（`SS_THRESHOLD`）：`T` 十字横杠、`j` 底钩、`E/F` 中横都能保住；
  1× 阈值 110 会丢。CJK 仍走 1× 阈值 110（笔画密，够稳）。
- 变体字体必须先钉字重：`Montserrat[wght].ttf` 默认 weight 100，不钉就是一堆细点（已修，仍保留
  `weight_regular`）。
- 码点集：GB2312 汉字 6763 + 常用标点 + `°`/`℃`（6783 个）。
- 产物：`firmware/core/src/font_ascii_16.cpp`（27.9 KiB）、`font_cjk_16.cpp`（1.9 MiB）。
  `font.hpp` 16 px 家族 `kMetrics{8, 22, 8, 22, 16, true}`：glyph_h=cell_h=22（盒=行距）。

## 4. 版面（firmware/core/src/ui.cpp）

- **顶带**：`no_top_band` 板（无触摸）`top_h = 36`。一开始直接置 0 让页头顶格，结果页头左侧
  状态圆点（r≈20）被圆弧切——240 屏安全区 206 px、圆心 (120,120)，点圆心落在 (41,79) 时
  半径已触弧。固定 36 px 让位后点圆心 (41,75)，最远墨迹 111 < 120，安全。
- **正文**：406… `content_h = 206 - 36 - 44 = 126`，行距 22 → 5 行容量，`body_rows_cap=4`。
  圆屏全宽行只能落在 panel y 52..188（弦长 ≥198 px 的区间），4 行块 + 块内居中（`slack/2`）
  正好在窗口内。
- **状态点**：`draw_indicator`
  - Ready：实心 `r*2/3`，不动（原来呼吸，脉冲最大 r 会顶弧）。
  - Responding 且未出声（工具在跑/首帧未播）：呼吸 `r*(8+pulse/3)/12`；`headline = Running`。
  - Responding 已出声：`headline = Speaking`，点画成电平条。
  - 回复完成停 Bringing 屏：`headline = Ready` + 正文。
- **脸与顶带重绘坑**：机器人脸（hero）现在画从 area y=0 起（整块玻璃），天线才不被顶带裁。
  切换 hero→文字页那一帧必须把 4 个 band 的哈希全部作废，否则页头带“内容没变就不重画”，
  会把脸残留的天线球最底几行留在屏幕上（表现为词上方多个白点）。修法：进入 bands 路径时
  若 `hero_valid_` 为真 → `hash_[0..3]=0` 一次。
- **温度折叠**：`i18n::fold_to_font` 增加 `°C/°F → ℃`；app 的远程文本（reply/transcript/
  card/prompt/notice）统一走 fold，屏上不再出现「20？」。

## 5. 测试口径

- **规范口径**（`HG_FONT_CELL=12`，各板出厂字体）：`hg_core_tests` 全绿（0 失败）。
- **16 px 自测环境**：本轮把与脸/布局绑定的断言改为**与字体度量无关的不变量**（换行词不拆、
  列数按 `font::advance` 逐字相加、prefix 只在字形边界切），并给一批「12 px 专用」用例加了
  字体门控（battery 带、QR、dashboard 行数、i18n fit 只查 moji 面板）。
- **2026-11-06 实测**：16px 口径仍红 **9 项测试、22 个断言**——字体度量 4 项、canvas 2 项、
  i18n 2 项、settings 像素 1 项，全是按 12px 定死的期望（固件行为本身没错）；其中 i18n fit
  的 3 处西语超长用户不用西语，不影响。收口办法是把这 9 项按字体面重钉，别让出货配置长期红着。
- 16 px 面板的 i18n 拟合契约现只校验 moji 几何（安全区 860‰、无顶带），但 fit 测试在 moji
  几何下仍有 3 处西语超长未过（见上条）。

## 6. 实测清单（2026-11-06）

- 模拟器 `sim-moji` 六景（待机/Thinking/回复首帧/回复中/回复完/卡片）逐像素核对：
  Running=7 字母、Ready=5 字母；黄点两页 bbox 相同 (29..57, 63..91)；词上方只剩 i 的点与 d 的竖笔。
- 真机 0.4.0 已烧录（app-only，`tools/flash_app.ps1`），`hermes gadget devices` 回报 0.4.0。

## 7. 天线球＝连接状态灯（2026-11-06 用户拍板）

- 脸页（hero）把天线球按 `m.link` 上色：在线绿 `rgb(61,214,140)`、连接中黄 `rgb(242,201,76)`、
  离线红 `rgb(242,95,92)`；**天线杆始终白色**，只有球变色（`robot::draw(..., antenna)` 第 10 个参数）。
- 顶部独立连接小点取消：`draw_top` 对 `no_top_band` 板直接 return（顶带只当弧线让位）。
  理由：原小点与脸/天线抢同一片天空，且离线时会整屏切到 Offline 页，独立点是冗余信息。
- 天线同时加长：设计坐标杆 78→56、球心 y=49（原来 78→64、球 57），杆 +6 设计 px，
  球顶实测从 panel 46 抬到 39，仍在玻璃内（240 圆屏顶弧在 y=0）。
- 实测：`sim-moji` 在线=绿、断网（`sim.set_network(False)`）=红，杆白；文本页（Running/Ready）
  顶部无残留点、左侧大状态点照旧。
